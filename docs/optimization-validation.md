## 更新既有数据库

旧数据库必须先执行 `sql/mysql8-soft-delete-migration.sql`，只增加 `device.deleted_at` 列，不能使用重新建库或清库代替。新库使用 `sql/mysql8-schema.sql` 即包含该列。

删除设备后序列号保留且不能重复注册，以保证历史属于同一设备。普通设备列表不显示归档设备；`GET /api/device?includeDeleted=true` 用于历史查询。删除后的在途作业不能新增测量或告警。

## 本地素材回归

交付视频当前位于 `E:/platform-handover/platform-handover.zip`，先解压到测试素材目录，原 ZIP 保留。测试建议使用独立数据库，避免回放记录混入生产历史。

在 `frontend/.backend.local.properties` 中添加，例如：

```properties
waterflow.test-source.enabled=true
```

本机已设置 `waterflow.ffmpeg-path=C:/Program Files/Tencent/QQBrowser/22.0.7003.400/ffmpeg/ffmpeg.exe`。这是现有浏览器附带的抽帧工具，支持本次 MP4→PNG 回放，不代表已安装完整 FFmpeg。服务启动会检查可执行文件，路径缺失或不能运行时明确报错。部署其他机器需改为实际安装路径。

## 无效画面与真实遮挡

白底中央提示页的结构检测有边界，不等于 OCR；自然场景仍需要现场复验。建议把实际 9048 错误截图放在单独目录，配置：

```properties
waterflow.invalid-frame-template-dir=E:/water-test/error-frames
```

模板缩放比对，模板本身不能使用纯白或纯黑图片。视频尺寸必须与 `frame_width/frame_height` 标定值一致。视频源错误不产生测量和任何告警；真实黑屏/过曝等按连续帧统计遮挡告警，不向水情曲线填假数值。

按用户最新要求，已移除独立水面检测模型及相关配置。前端实际触发 `playing` 后向鉴权接口 `POST /api/ezviz/playback` 报告可播放状态，每 15 秒续期；获取地址、读取播放清单或仅触发 loadeddata 都不开始检测。后端只调度正在播放的设备，先抽取两帧并完成有效性和遮挡检查，再运行原有水情与漂浮物模型。停止播放、卡顿、换设备或离开页面会发送停止通知；异常关闭页面或通知丢失时，45 秒无续期后停止调度。多页面独立维护状态，单个页面停止不会中断其他仍在播放的页面；版本号阻止迟到的开启通知覆盖停止状态。

本地录像回归通过模拟播放就绪通知激活作业，不需要云端连接。该回归验证抽帧、原模型推理与持久化调用，未在生产库写入回放测量，也没有覆盖浏览器本地录像播放的完整页面链路。交付水情模型的水面框置信度固定为 0.99，属于数值编码输出，不能据此保证实际存在水面或测量精度；画面正常播放也不能证明标定正确。仍需现场标定与 TC-20 精度验收，页面保留趋势参考提示。

## 会话和运行状态

登录后 API 使用现有 Bearer token；浏览器 WebSocket 自动携带仅限 `/ws/realtime` 的 HttpOnly Cookie，不把长期 token 写到查询参数。WS 来源配置为 `waterflow.websocket-origins`，部署时设置页面实际 HTTPS 域名。反向代理需传递正确 `X-Forwarded-Proto`。会话存储为单实例内存，重启需重新登录；多实例需共享存储。

失败次数按本次服务生命周期累计，参数修改保留统计，服务重启清零。恢复成功清空当前 error 和连续失败次数，保留累计次数与最近失败原因。前端“近期采样正常”仅表示近期采样成功，不能冒充摄像头厂商在线状态。

运行状态增加 `runtimeEpoch`（本次服务启动时间）与 `runtimeVersion`（每台设备完成周期的递增版本），前端 HTTP 与 WS 都拒绝旧版本，避免旧响应回退失败次数。视频连接及卡顿超时从首次等待开始，重复 waiting/stalled 不延长截止时间。

测量和告警事务先锁定仍有效的 device 行。归档与事务写入按锁顺序完成：已归档后开始的落库被拒绝；正在提交的事务完成后归档才返回。已存在 OPEN 告警时不生成新截图；仅本次创建、没有被提交告警引用的截图在事务结束后清理，历史截图保留。提交结果不确定时保留图片，防止删除可能已经被数据库引用的文件；这种情况和进程崩溃可能留下未引用文件。此次没有扫描或删除既有截图目录。

漂浮物升级需同时配置 `waterflow.debris-class-count` 和逗号分隔的 `waterflow.debris-labels`，输出应为 YOLOv8 `(1,4+类别数,anchors)`。NMS 不用于水情模型的数值编码框。
